# TSManager 1.0.3 QA 测试报告

测试日期为 2026-11-11。测试机为 Windows 10 专业版 x64（19045），构建环境为 Node.js 25.2.1、npm 11.6.2、pnpm 10.24.0、Python 3.13.9 和 Electron 45.2.1。

| 范围 | 结果 | 验证内容 |
| --- | --- | --- |
| 构建 | 通过 | TypeScript 类型检查、Vite 生产构建、Electron 主进程构建、Vite 开发环境启动。 |
| 分组与项目 | 通过 | 在真实窗口创建分组、折叠和展开、创建与编辑项目、搜索、确认删除。验证删除分组会迁移项目、删除项目后本地文件仍在。 |
| 运行环境 | 通过 | PowerShell 与 CMD 实际启动 npm、pnpm、Python 以及 Vite TypeScript 项目，覆盖含中文和空格的目录。通过 HTTP 请求验证 Vite 返回已转换的 TypeScript 模块。 |
| 进程生命周期 | 通过 | 三项目并行、停止、重启后监听 PID 改变、Ctrl+C、超时后的进程树清理、异常退出进入历史、后台异常终止后释放端口。 |
| 终端与日志 | 通过 | 独立 PTY、ANSI 输出、交互输入、尺寸调整、全屏、清屏、终端隔离、历史日志、敏感变量值脱敏。持续输出超过 32 KiB 时，持久化日志和终端回放仍受设置上限约束。 |
| 端口 | 通过 | 识别 TCP 监听 PID 和项目归属，冲突阻止启动，拒绝通过外部终止接口停止受管理进程，校验外部进程身份后终止测试进程。 |
| Vite 配置端口 | 通过 | 在 Vite 7 和 8 上用带固定端口的脚本启动，覆盖 pnpm 与 npm。验证 HTTP 响应和进程归属均使用配置端口，项目脚本保留原值。解包版验证「实际监听」显示真实端口。 |
| 外部 Node.js 项目 | 通过 | 默认分组显示「结束进程」文字按钮和琥珀色「未监听」状态。解包版验证按钮可见、取消确认和确认结束。旧后台兼容测试验证补齐进程身份，并在确认时只结束旧后台仍报告为外部的进程。 |
| 本机网页终端 | 通过 | 浏览器 xterm 实时收到真实 Node 进程的带时间戳输出，输入可送达进程，刷新后可回放。已安装应用可从设置打开随包分发的网页工作区，并与桌面端共享同一个真实 PTY。自动化测试覆盖 Ctrl+C、未经授权及跨源请求拒绝。 |
| SQLite 升级 | 通过 | 从真实 1.0.1 后台切换到 1.0.3 解包版后台后，读取同一数据库里的项目、分组、设置、加密环境变量、运行历史和日志。 |
| 旧后台切换 | 通过 | 旧后台存在运行项目时保留其进程。停止项目后，新版自动切换后台并按配置端口启动 Vite。 |
| 窗口退出 | 通过 | 关闭实际 Electron 窗口后按设置保留项目并重新连接，切换为停止所有项目后关闭窗口会释放端口。 |
| 安装与卸载 | 已验证上一构建 | 上一构建通过当前用户安装、安装后运行及卸载检查。1.0.3 通过解包版和隔离数据目录验证升级，NSIS 配置保留用户数据。 |

可通过 `npm test`、`npm run test:ui` 和 `npm run test:web` 重跑测试。安装后的 UI 测试以 `TSMANAGER_TEST_EXE` 指向安装目录中的 `TSManager.exe`。升级回归使用 `node tests/upgrade.mjs`，旧版路径设置见 [README](../README.md)。测试服务及数据库使用隔离的临时目录。

本次未执行真实系统关机或注销，也未在其他 Windows 版本上复测。外部浏览器和原生文件夹选择器的实际操作未纳入自动化。
